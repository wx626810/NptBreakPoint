# NpHv 克隆重定位修复报告：克隆页位置无关化（0x50 蓝屏根因修复）

> 基线：`output\NpHv.sys`（Release, 82,768B, 2026-08-27 01:23）/ `output\NpHv.pdb`
> 触发现场：Win11 24H2 (26100.8036) 4 核，`svchost.exe`，0x50 PAGE_FAULT_IN_NONPAGED_AREA
> 性质：方案C 克隆执行机制的结构性修复 —— **为克隆页引入完整 x64 重定位器**，
> 附带修复展开 blob 覆盖镜像页、克隆/影子池 NX、WVM 补丁空参桩三处隐患。

---

## 一、0x50 蓝屏根因（dump 证据链）

```
0x50, Arg2=0x11（not-present + EXECUTE），Arg3/Arg1 = ffffce8a890e0170（取指野地址）
AV.Type: Execute；PROCESS: svchost.exe；开机 71s（= 点击"隐藏调试开"后瞬间）
u nt!KiSystemServiceCopyEnd：
    fffff8027e4be350  mov rax,r10
    fffff8027e4be353  call rax          ← 取指 ffffce8a890e0170 → #PF → 0x50
r 寄存器：r10 = ffffce8a890e0170（野地址）
!pte ffffce8a890e0170：PTE 不存在（大页 NX）→ 系统区野地址
```

**机理**：svchost 的系统调用命中被 hook 的 Nt\* 服务 → 跳板放行 →
**函数体在克隆页（池地址 CloneVA）执行** → 克隆体内第一条 `call rel32` / `[rip+disp]`
按 CloneVA 计算目标（disp 是原地址语义）→ 跳到池垃圾 / 读出垃圾指针 →
执行流被甩进 `ffffce8a...`（PFN 数据库区）→ 取指 0x50。

**方案C 的核心缺陷**：函数体从原虚拟地址搬到 CloneVA，但 x64 指令是位置相关的
（`call/jmp rel32`、`[rip+disp]`），克隆拷贝没有做重定位 → 任何出块相对引用全部错位。
这是 100% 必现的结构性缺陷——旧版（物理页交换、原 VA 执行）不存在此问题。

## 二、修复设计：克隆页重定位器（NpReloc）

新模块 `services/NpReloc.cpp`（纯逻辑，WDK 无关，可主机验证）对 8KB 源块
（[原页 P][镜像 P+0x1000]）做完整重定位：

| 指令形式 | 改写 | 长度 |
|---|---|---|
| `call rel32`（出块） | `mov r11,imm64; call r11` | 5→13 |
| `jmp rel32/8`（出块） | `mov r11,imm64; jmp r11` | 5/2→13 |
| `jcc rel8/32`（出块） | 反向短跳 + r11 跳板 | 6/2→15 |
| `lea r,[rip]`（出块） | `mov r,imm64`（movabs） | 7→10 |
| `mov r,[rip]`（出块） | `movabs r,addr; mov r,[r]`（**目标寄存器持地址**） | 7→13 |
| `movzx/movsx r,[rip]`（出块） | 同上（全宽写安全） | 7→13/14 |
| `mov [rip],r` / `cmp r,[rip]` / RMW / XMM 载入 / cmovcc / xadd / test | `mov <死寄存器>,imm64; <原指令以 [r] 重编码>` | 7→12~17 |
| `nop [rip]` | `nop` | 7→1 |
| 块内相对目标 | 保持相对 + 重算位移（布局变化后）；rel8 统一扩为 rel32 | — |

关键机制：

1. **代码区间隔离（.pdata）**：仅对 `.pdata` 覆盖的代码区间做重定位；区间外的
   跳转表/对齐/填充数据**原样复制、绝不解码**（QSI 的 0x140AE2160 跳转表等）。
   起始于本块之前的跨页条目（前一函数尾部）被排除——其块内指令边界未知，
   无法安全重定位。
2. **目标寄存器持地址（RIP_FORM_DEST）**：`mov r64/r32,[rip]`、`movzx/movsx`
   改写为 `movabs <目标>,addr; <op> <目标>,[<目标>]`——只改写原指令已写的寄存器，
   **零额外破坏**，无需存活分析。
3. **存活分析（记忆化 DFS）**：存储/RMW/XMM/cmov 等需暂存寄存器的形式，从改写点
   沿控制流前向扫描"先写后读"证明寄存器死亡；记忆化保证有界终止，环上乐观假定
   （首访已检查自身读写），任何不确定性保守判活。找不到死寄存器 → 拒绝安装
   （宁可失败不可错误）。
4. **偏移映射表**：以【重写指令源跨度结束边界】为键（`OrigOff+OrigLen → NewOff+NewLen`），
   保证 MapLookup(下一条指令起始) 正确；NPF 重定向与跳板跳回经映射表换算。
5. **块首尾部恒等单步**：被排除的跨页尾部（offset < 首区间 Beg）由 NPF 处理器
   以"恒等 + TF 单步"从**真页**执行一条指令（相对寻址全部命中原地址），#DB 收口
   立即重武装。该区域不是 hook 目标函数本身，确定性拦截不受影响（窗口=单指令）。

| 2 | NpHookBuildCloneUnwind | blob 从 `CloneVA+PAGE_SIZE`（覆盖镜像页！）挪到 `CloneVA+NP_RELOC_MAX_OUT`；`UnwindData = 0x4000 + off`；条目 Begin/End 经映射表换算 |

## 四、验证（主机侧，本机 ntoskrnl 26100.9168 与测试机同族）

新增 `NptHook/tests/NpRelocTest.cpp`（MinGW g++ 编译，无 WDK 依赖）：

```
== NtQueryInformationProcess @ RVA 0x995240 ==   out=0x27cc 膨胀+0x7cc map=328  [ok]
== NtQuerySystemInformation  @ RVA 0xAE20C0 ==   out=0x2fe4 膨胀+0xfe4 map=598  [ok]
== RtlLookupFunctionEntry    @ RVA 0x232140 ==   out=0x24e1 膨胀+0x4e1 map=242  [ok]
全部通过（失败 0）
```

校验项：① 重定位输出全指令可解码；② 块内相对跳转目标落在指令边界；
③ 映射表单调一致；④ 数据区（区间外）字节原样；⑤ **语义校验：r11 跳板必须带
REX.B（`49 BB imm64 41 FF D3/E3`），裸 `FF D3`（call rbx）判错；imm64 必须是内核地址**。
（目检：RLFE 的 `movaps xmm1,[rip]` → `movabs rax,<addr>; movaps xmm1,[rax]`；
`movsd`、`cmp rbx,[rip]`、`cmovne rdx,[rip]` 同理。）

解码器回归：`TestDisasm` 127 个手工用例全部通过（NpDisasm 重构未改变长度语义）。
全 .text 线性解码覆盖率：指令 297 万，失败字节 8,938 / 10,617,228（0.084%）。

驱动构建：MSBuild Release x64 **0 error**，NpHv.sys 82,768B。

## 五、已知边界与后续

1. **探测期（2026-08-25 报告第 4 项）计时侧信道仍存在**：叶子常驻 NX，页访问
   产生 #NPF+#DB 往返；重定位不改变该成本。
2. **块首尾部（前一函数跨页流入）单指令恒等窗口**：该区域执行走真页，中断可
   拉长窗口（同旧版数据单步边界，报告第六节第 2 项同款分析，ISR/DPC 不调
   Nt 层，实用概率趋近零）；hook 目标函数本身的确定性拦截不受影响。
3. **多页限制**：克隆块仍为 2 页源（8KB 重定位、上限 16KB 输出）；函数体若
   顺序流超过 2 页且落入克隆第三页区域会越界——当前 6 个目标（5 Nt 封装 +
   RtlLookupFunctionEntry）均在预算内（实测最大 0x2fe4）。
4. **重定位失败即拒绝安装**：任何函数出现不支持的形式/无死寄存器/容量不足 →
   该 hook 不装（dbghide 整体回滚并报错），绝不产生错误代码。
5. **待真机验证**：加载 → `隐藏调试开` → protect PID → 附加 → F2 断点 →
   自检九项零翻转；`sc stop` 卸载无蓝屏。日志应出现
   `NpHookInstallHook: clone 0x... (len=0x..., map=...) relocated ok`。
6. **报告事故说明**：修复过程中 `NpHook.cpp` 的注释文本因一次编码往返事故
   （PowerShell 按 ANSI 读取 UTF-8 文件）发生乱码（注释内出现 `?` 与替换符），
   结构性问题已全部修复并验证编译 0 error；注释可读性待后续清理，不影响功能。
