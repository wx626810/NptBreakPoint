## 1. 审查方法与范围

- **逐行人工通读**：`NptHook.cpp`、`core/`（NpHv / NpHvArchSvm / NpHvVmExit / NpHvPower / NpPlatform / NpSelfHide / x64.asm）、`services/`（NpHook / NpBreakPoint / NpDebugHide / NpMemAccess / NpDevIoctl / NpLog / NpProcessHide / NpDisasm）、关键头文件（NpTypes / NpSvm / NpIoctl / NpConfig）。

## 4. 本次发现的蓝屏问题（分级）

### 🔴 High（可实际触发）

**H1 CustomCode 注入代码执行中 UAF** — `NpDevIoctl.cpp`
`unhook/unhookall` 立即 `ExFreePoolWithTag(CodePtr)`，而跳板回调可能正在执行这段机器码（HOOK_INFO 走退休链，唯独代码缓冲被漏）。高频函数上几乎必撞窗 → 执行已释放池 → 0x50 / NX 执行。注释自己写了 UAF 防护理由却漏了此指针。

**H2 物理直读对失效 PFN 无防护** — `NpMemAccess.cpp`
`MmGetVirtualForPhysical` 对失效输入**不会返回 NULL**（NULL 检查形同虚设）；页表遍历与实际读取之间存在窗口，目标页换出/PFN 重用后返回垃圾 VA → 直接解引用 → **0x50 且 SEH 拦不住**（与历史 SSDT 蓝屏同根因）。X64DBG 的 RVM 无痕读路径高频暴露。

**H3 用户态断点物理页无生命周期管理** — `NpBreakPoint.cpp InstallEx`
用户页只在安装瞬间抓一次 GPA，不锁页。目标页换出/进程退出后物理帧被重用，而全 CPU NPT 仍把该 GPA 重定向到旧影子页 → 任何核访问新用途的帧都被劫持 → **全局内存破坏级蓝屏源**。内核地址断点无此问题。

### 🟠 Medium（条件触发）

**M1 注入 #PF 未设置 VMCB.CR2** — `NpHvVmExit.cpp`
AMD 规范：EVENTINJ 注入 #PF 时 CR2 取自 VMCB 保存区，代码从未写入 → Guest 收到陈旧随机 CR2，内存管理判定错乱 → Guest 内核蓝屏。触发面：非 present NPF（含读监视页 R=0 被取指的路径）、物理映射超 512GB NPT 覆盖（Resizable-BAR 等 MMIO 可在 512GB 以上）。

**M2 断点/监视卸载"单步占用"检查是无锁扫描** — `NpBreakPoint.cpp`
TOCTOU：扫描判"不在单步"→释放，同时某核恰好进入单步（handler 持 g_BpListLock 设置 SingleStepOwner，扫描方不持锁）→ #DB 解引用已释放结构 → UAF。

**M3 vmmcall 前运行标志检查 TOCTOU** — `NpHv.cpp` / `NpBreakPoint.cpp`
"先查 g_HypervisorRunning 再 vmmcall"挡不住检查与执行之间完成去虚拟化 → #UD。窗口微秒级，需卸载与复位 tick/bpcont 恰好相撞。

**M4 电源回调 DISPATCH 分支延迟工作项赌睡眠时序** — `NpHvPower.cpp`
睡眠通知以 DISPATCH 到达时去虚拟化被推给工作项；若系统在项执行前冻结 CPU，SVME 带着 S3 进出 → 唤醒后首个 vmmcall 异常。另 `g_PowerWorkPending` 检查-置位非原子。

**M5 NpLogTeardown 忙等超时仍 ZwClose、卸载照常推进** — `NpLog.cpp`
与复位线程版（超时保留句柄）不对称；且两者超时后 unload 都继续——线程真卡死则驱动镜像照样卸载。

**M6 prochide 名字表快照 UAF**（8-22 新代码）— `NpProcessHide.cpp`
`IsNameHidden` 持锁拷贝 UNICODE_STRING 值后放锁再用，并发 Remove/ClearAll 释放缓冲 → 读已释放池。

### 🟡 Low / 备注

- dbghide/prochide Teardown 位于卸载第 8 步（晚于第 7 步 FreeRetired）→ 每次 load/unload 循环泄漏退休链内存。
- `s_NtdllBase` 缓存 PEB 用户地址跨上下文复用且 `NpGetModuleExport` 无 SEH。
- `wcslen(req->Name)`（64 wchar 定长无终结符）属"信任 R3"既定策略。
- 死代码 `NpFindServiceTable`（LSTAR 扫描无预检）无人调用，建议删除防误用。

## 5. 已实施修复（2026-08-23）

| 编号 | 文件 | 修复方案 |
|---|---|---|
| H1 | `NpDevIoctl.cpp` | unhook 不再立即释放 CodePtr：`RtlSecureZeroMemory` 清零（抹机器码痕迹）→ 挂退休数组（容量 128，满则告警+故意泄漏）→ `NpDevTeardown` 在虚拟化关闭后统一释放。UNINSTALL_HOOK / UNINSTALL_ALL / Teardown 三处接入 |
| H2 | `NpMemAccess.cpp` | 读路径改 `MmCopyMemory(MM_COPY_MEMORY_PHYSICAL)` 逐页拷贝，失效帧优雅失败；写路径改 KeStackAttachProcess+直接虚拟写（CoW/换页由内存管理器处理，依旧无痕）；页表遍历 Qword 读加 `__try` 二道防线 |
| H3 | `NpBreakPoint.cpp` | 用户态断点安装时 `IoAllocateMdl`+`MmProbeAndLockPages(IoReadAccess)` 锁定物理页；MDL 随断点生命周期，四个释放点（立即释放/退休/FreeRetired/Teardown）统一解锁回收。已知限制：CoW 换新帧后静默失效（不崩） |
| M1 | `NpHvVmExit.cpp` | `NptInjectPageFault` 增加 FaultAddress 参数，注入前写 `VMCB.StateSaveArea.CR2`（GPA 尽力值语义，注释注明） |
| M2 | `NpBreakPoint.cpp` | 抽出 `NpBpIsSingleStepOwned()`，断点卸载/UninstallAll/监视卸载三处占用扫描移入与 Active=FALSE 同一次自旋锁临界区，与 #BP/#DB handler 构成完整互斥 |
| M6 | `NpProcessHide.cpp` | `IsNameHidden` 全程持 `g_HideLock` 比较（≤16 短名，微秒级），删除悬垂快照窗口 |
