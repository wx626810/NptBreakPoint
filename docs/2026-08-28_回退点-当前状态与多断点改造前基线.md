## 7. 本次改动记录（改造过程中追加）

### 7.1 断点删除：overlay 闭环（2026-08-29 已解决，实机验证）

**用户明确**：目标是解决 x64dbg 的断点问题，不是加外围接口 —— 该方向维持，
最终也**没有**走外围接口，而是在驱动侧把删除闭环补上了。

**曾长期表现**：运行期删除断点后仍被断下（删除失效）。根因三层：
1. 无痕断点读写不对称（写 0xCC 被拦截、读返回真值 → 调试器认为断点没了）；
2. **overlay 判据用 `NpPseudoDbgFindByDebugger`，真实附加模式下恒 FALSE →
   overlay 从未生效** → TitanEngine 删除时读验证读到 0x48 → 不写回原字节；
3. zombie reap 的 target=0 盲区（兜底不触发）。

**修复**：`NpDebugHideIsDebuggerOf`（DAP 锚点表）+ overlay 判据改用它 +
`NpBreakPointDeleteByCcWrite` + reap target=0 不过滤。实机验证：
**删除断点成功、不再断下**。详见主报告第 26 节。

### 7.2 同页多断点：页级共享影子（2026-08-28 已实现）

**要解决的问题**：NPT 每 4KB 页只有一条叶子，原实现 `NpBreakPointIsPageOccupied`
让同页第二个断点直接返回 `STATUS_ALREADY_REGISTERED`。x64dbg 的"步过"会在
同一页下临时断点 → 静默失效，步过不可靠。

**改动（全部在 `NptHook/services/NpBreakPoint.cpp`）**：

| 项 | 内容 |
| --- | --- |
| 新结构 `BREAKPOINT_PAGE` | 持有 PageGpa / OwnerProcess / UserPageMdl / ShadowPage0 / ShadowPage1 / 两个 PA / RefCount / BpListHead |
| `BREAKPOINT_INFO` 改别名 | ShadowPage0/1、两个 PA、UserPageMdl、OwnerProcess、PageGpa 全部改为指向页记录的**非拥有别名**；新增 `Page` 指针 + `PageLink`（挂 `Page->BpListHead`）。所有读路径零改动，只有所有权路径改 |
| 全局链表 | `g_BpPageListHead`（活动页）、`g_RetiredBpPageList`（延迟释放） |
| `NpBpPageRebuildCc` | 影子页0 整页拷入影子页1，再按该页**全部**活动断点偏移打 0xCC |
| `NpBpAttachToPage` / `NpBpDetachFromPage` | 挂载填别名 / 摘除减引用；归零则页转入退休链。返回 `NP_BP_DETACH_RESULT` 告诉调用方"还有断点要重建 CC"还是"最后一个要恢复恒等" |
| 页内查找 | `NpBpPageFindHalted` / `NpBpPageFindPausedContinue`(按 faultRip+线程) / `NpBpPageFindDeletePending` / `NpBpPageHasPaused` / `NpBpPageFindByAddress` |
| `#NPF` 取指 | 改为**先按页查页记录，再按 faultRip 匹配具体断点**。三路判定顺序：HALT → continue 单步 → 删除确认 → 取指切 CC |
| `InstallEx` | 同页断点不再互斥：命中已有页则复用（不新建 MDL / 不重复 ObReference / 不重复分配影子页），只重建 CC 并重新武装；同地址重复安装仍返回 ALREADY_REGISTERED 供调用方 ReArm |
| `Uninstall` | 按 `detach` 结果分流：页上还有断点 → 重建 CC + `ConfigureOnProcessor`；最后一个 → `RestoreOnProcessor` 恢复恒等 |
| `#DB` 单次断点 | 同上分流（原来无条件恢复恒等，会把同页其余断点一起废掉） |
| 复位线程 | 由遍历断点链改为**遍历页链**（同页 N 个断点只处理一次）；跳过条件改为"页内单步中 / 页内有暂停断点" |
| `NpBreakPointIsHaltedPage` | 改为按页判断（看门狗豁免，原来只查链表首个断点会漏判） |
| 清扫线程 | 每轮调用 `NpBreakPointFreeRetired()`，回收 VMEXIT 上下文摘除的断点结构 |
| `NpBpPageFreeResources` | 取代 `NpBpFinalRelease`：解锁 MDL → 释放影子页 → 解引用进程 → 释放页记录 |

**守住的不变量**：
- 每页只 pin 一次：第一个断点建 MDL，最后一个断点删除时释放；同页 N 个断点从
  N 个 MDL 降为 1 个，锁页只减不增；
- 解锁先于最后一次 `ObDereferenceObject`（0x76 的唯一根因）；
- VMEXIT 上下文不释放内存：bp 挂 `g_RetiredBpList`、页挂 `g_RetiredBpPageList`，
  由清扫线程 / Teardown / FreeRetired 在 PASSIVE 回收；
- `NpBpIsSingleStepOwned` 扫描与 `NpBpDetachFromPage` 必须在同一把
  `g_BpListLock` 内完成（防 TOCTOU UAF）。

**断点与 NPT Hook / 监视仍然按页互斥**（未改动）：它们抢同一条叶子。

**已知限制**：
- 共享叶子的单指令窗口：A 暂停期间 B 命中照常走 `CC→#BP`；但 A 的 continue
  单步窗口内（`NX=0`）同核其它线程取指 B 会漏掉这一条指令。架构下限。
- 复用页时不重新快照真实页：新断点的影子内容沿用该页首次安装时的快照。
  正常代码页不变；若绕过 WVM 钩子改了页内容，影子会滞后（WVM 路径已由
  `NpBreakPointRefreshShadowOnPatch` 覆盖）。

Debug/Release 均构建通过，**零警告**。

### 7.4 进程退出通知：legacy 兜底（2026-08-28 已实现）

见主报告第 24 节。要点：
- `PsSetCreateProcessNotifyRoutineEx` 失败 → 退 legacy
  `PsSetCreateProcessNotifyRoutine`（不过 `MmVerifyCallbackFunction`）；
- 新增 `NpBreakPointProcessNotifyLegacy` + `NpBreakPointUninstallByPidNoRef`
  （按 PID 匹配，不依赖 `PsLookupProcessByProcessId`）；
- `g_LegacyProcessNotify` 记录走哪条路，Teardown 按同一路移除；
- 500ms 清扫线程保留为最后兜底。

### 7.3 跨核 ICache 失效（2026-08-28 已实现）

- 新增 `NpBpInvalidateShadowCaches`：对影子页0/1 调 `KeInvalidateRangeAllCaches`。
- 调用点：安装（含同页新增断点）、卸载后重建 CC、补丁刷新。
- **刻意不放进 `NpBpPageRebuildCc`**：该函数会在 `g_BpListLock`（DISPATCH_LEVEL）
  内被调用，而 `KeInvalidateRangeAllCaches` 发 IPI 等待其它核应答，持锁调用有
  死锁风险。一律在释放锁之后调用。
