# NpHv 方案C 改造报告：克隆页确定性拦截引擎 + 用户态隐匿补丁

> 基线：`output\NpHv.sys`（Release, 69,352B, 2026-08-26 02:07）
> 备份：`backups\NpHv-pre-planC-20260825\`（71 文件，改造前完整源码）
> 性质：hook 引擎结构性升级 —— 从"三视图轮换"迁移到"整页克隆 + 永久武装"，
> 并新增 **PatchView 用户态隐匿补丁**子系统

---

## 一、背景：原方案的 C 态暴露窗口

原 INT3 影子 hook 采用三视图轮换状态机：

```
A(S0+NX 武装) ──取指#NPF──→ B(S1+INT3) ──#BP──→ 跳板 ──跳回真页+N──→ C(S0 可执行)
                                  ↑___________ 窗口：C 态期间同核穿透 ___________|复位线程(定时)
```

函数体必须在真页 P 上继续执行，而 AMD NPT 无 execute-only 位，只能把整页切到
干净可执行（C 态）。C 态自锁（可执行页不再产生 #NPF），只能靠周期 vmmcall 解锁。
**窗口内同核所有线程调用被 hook 函数完全穿透。**

实测证据（2026-08-25 上午，4 核 VM）：
- 自检工具七次扫描结果翻转（DebugPort 在真值/伪造值间跳动）
- 任务管理器中 x64dbg 间歇性闪现
- x64dbg 附加时的 NtDebugActiveProcess 调用整体绕过 DAP hook
  （日志缺失 auto-protect 行），BeingDebugged 未清除、0xCC 物理落地

## 二、方案 C 核心思想

**与其管理"门什么时候开"，不如让门永远焊死。**

```
安装时：
  P      真页            → 叶子锁死 A 态（S0+NX），永不解除武装
  S0/S1  影子对          → 保留（触发器机制不变）
  CLONE  整页克隆        → 4KB 对齐非分页池，P 的逐字节拷贝，一个字节不改
  跳板                  → 过滤回调 + 序言副本 + jmp CLONE+N   ← 唯一改动点

运行时：
  入口取指 → #NPF(A) → B(INT3) → #BP → 跳板[过滤逻辑] → jmp CLONE+N
  函数体在克隆上执行 —— 普通池内存天然可执行，零 VMEXIT、零叶切换
```

**确定性证明**：叶子恒为 A 或 B。A 态取指必陷阱；B 态内容是 INT3 必陷阱。
不存在"可执行且无陷阱"的形态 ⇒ 每一次调用必然经过过滤逻辑。∎

| 场景 | 协议 |

## 六、已知限制（诚实清单）

1. **异常展开（已解决——元钩子方案）**：
   内核未导出任何动态展开表 API（本机 ntoskrnl 导出表已核实：无
   RtlAddGrowableFunctionTable / RtlInstallFunctionTableCallback）。落地方案为
   **递归应用自身引擎**：对 `RtlLookupFunctionEntry` 本体安装一个方案C 元钩子，
   查表请求的 ControlPc 落在任一克隆区间时，返回预构建的重定位条目数组指针
   并将 ImageBase 置为克隆基址——展开器随后读取的 UNWIND_INFO 位于克隆分配
   后半段的 blob 副本内，完全自洽。
   **精确性边界**：仅收录无语言处理器标志（EH/UH）且 CHAININFO 链目标同页的
   帧；带处理器的帧整体放弃精确化（回退旧的叶子帧假设）。五个 syscall 封装
   属无处理器帧，实际全覆盖。异常处理器的寻址问题因 ImageBase=克隆基址而
   天然正确——handler 代码本来就在克隆上执行。
2. **数据单步窗口——精确机理**：单条指令不可分割、指令边界之外无调度点，
   "其他线程凭空插入执行"不存在。同核穿透的**唯一载体是中断拉长窗口**：
   外部中断在"恒等已开、TF 已置"的边界被优先受理时（AMD 事件优先级中
   INTR 可先于 #DB 陷阱），叶子保持恒等贯穿整个 ISR/DPC 处理时长
   （微秒~毫秒级）。穿透需要 ISR 路径调用被 hook 函数 + 恰好被观测——
   而 DPC 级不调 Nt 层 API，实用概率趋近零。
   *状态机自愈收敛性：即便 ISR 内踩中 INT3 使叶子回 A，被打断线程恢复后
   会重新撞 A 态走完整流程，所有交错路径最终收敛回状态机。*

3. **B 态 CC 可见——精确机理**：基础窗口 = 一条指令槽（纳秒级），
   单指令内无调度点；同核穿透唯一载体同为中断拉长（延伸至 ISR 时长）。
   跨核读取不受影响（他核叶子仍在 A 态，读取经 DataFault 正确服务）。
   可见后果为入口首字节的 CC——归因方向是"传统 INT3 断点"而非
   hypervisor，反而误导对手。

4. **计时侧信道（重要度高于 2/3，方案C 在 AMD 上的结构性代价）**：
   叶子常驻 NX ⇒ 每次数据访问这五个页都触发一对 #NPF+#DB 的 VMExit
   往返（约 1~3μs）。整页 CRC 类校验会比邻居页慢约千倍——具备内核页级
   精细计时能力的对手可量化出"这几个特定页处于特殊监控"，从而泄露
   hook 点位清单。缓解选项（按代价排序）：接受现状（主流 AC 不做此检测）
   / #DB 收口时保持恒等 X 微秒宽限期再收口 / 识别连续故障风暴判定为批量
   扫描后开放恒等交由复位周期收口。

5. **同页互斥维持现状**：一页仍只允许一个占用者（Hook 与断点互斥）。
6. **目标进程退出自动拆除** ✅ 已实现（PsSetCreateProcessNotifyRoutineEx）。
7. **单次写入 ≤512 字节且不可跨页**：跨页补丁已由双页组原生支持；
   超出 512 字节的单次写入仍回落真实写（大编辑拆分提交）。
8. **补丁页与断点/Hook 同页互斥（强制拒绝）**：ApplyWrite 检测到页已被
   Hook/断点占用时拒绝创建视图并打日志——两套叶状态机不混用。
9. **用户态 SEH/C++ 分发侧展开**：ntdll 元钩子为下一阶段（见 B1 设计）。
10. **MDL 页锁定的可检测面**：`MmProbeAndLockPages` 会在 PFN 数据库中
    对目标物理帧的引用计数 +1。具备内核驱动的高级反作弊理论上可通过
    遍历 PFN 数据库检测到异常引用计数。实际风险极低：需要对手精确知道
    检查哪些帧、且能区分正常内核持锁与异常锁定。若需彻底消除此痕迹，
    可改用 R3 `SetProcessWorkingSetSize` 提高工作集下限替代 MDL 锁定
    （零内核痕迹，效果等同）。

## 十、PatchView 用户态隐匿补丁（v2 双页组，新增子系统）

### 语义矩阵

| 访问类型 | 谁 | 看到/执行 |
|---|---|---|
| 执行 | 任何线程（含目标自身） | 补丁后字节 |
| 数据读 | 安装者/查看者（DebuggerPid 或写入者 PID） | 补丁后字节 |
| 数据读 | 目标自检 / 其他进程 / 内核扫描 | 原始字节 → **CRC 通过** |
| 数据写 | 查看者 | 落克隆，累积为补丁 |
| 数据写 | 受害者本人 / 外部 / 内核直写 | 落真页（公开变更），克隆同步保留分歧偏移 |

### v2 双页组模型

一个视图覆盖连续 **8KB VA 窗口** [VaLo, VaLo+0x2000)，解决两类跨页问题：

1. **跨页补丁写入**：自动拆分到两张克隆子页，不再静默降级；
2. **函数体跨页执行**：顺序执行流在克隆块内无缝连续（16KB 块布局：
   CleanLo/CleanHi/CloneLo/CloneHi），不存在越界窗口。

### 接入方式（自动转换）

x64dbg 对受保护进程可执行页的任何非 CC 写入（WPM），由 WVM 分类器自动
转为隐匿补丁：写入者 PID 自动进入查看者名单。撤销 = 再写回原字节。
数据页写入不受影响（功能性数值修改必须真实生效）。

### 实现机制要点

- 武装态 = 两页叶子 Present=0：AMD 无 execute-only 位，唯有 not-present
  能让取指与数据访问同时陷入 #NPF 由 VMM 按类型+身份裁决；
- 执行路径零叶操作：#NPF 后 RIP 直接重定向到克隆同偏移；
- 观察者分流：数据违例时按 `PsGetCurrentProcessId()` ∈ 查看者名单选源帧；
- 若进入前 TF 已置（调试器正在单步）：收口时不消费 #DB、不清 TF，
  把单步事件交还调试器（防吞步进）;
- 非观察者写后的克隆同步采用**分歧保留算法**（对比 CLEAN 判定分歧，
  分歧保留、无分歧跟随现实），真页读取经 `MmMapIoSpace` 物理映射
  （避免跨进程地址空间解引用错误）;
- 受害者退出：`PsSetCreateProcessNotifyRoutineEx` 回调立即拆视图 +
  恢复恒等（防帧复用误伤）；驱动卸载时反注册通知。

## 十一、附录A：异常穿越机制详解

**什么是"帧"、什么是"穿越"**：调用链 `[调用者] → [被补丁函数] → [内部助手]`。
每个函数在栈上占一段"帧"。内部助手抛出异常时，分发器从最深帧开始逐帧
向上搜索处理程序；每经过一帧都要执行"展开"（Unwind）——恢复该帧保存的
非易失寄存器、定位返回地址、弹出栈空间。这要求知道每帧的**帧布局描述**。

**描述从哪来**：x64 编译器为每个函数生成 `.pdata`（RUNTIME_FUNCTION 数组）
和 UNWIND_INFO。运行期 `RtlLookupFunctionEntry(RIP)` 按 RIP 所属模块查表。
**查不到（返回 NULL）= 内核按"叶子函数"假设处理**：直接把 [RSP] 当返回
地址弹出——对真正的叶子成立，对有局部存储的非叶帧就是跳向垃圾地址。

**什么导致穿越补丁帧**：只要异常从被补丁函数的内部（或其下游调用链）
向外传播且处理程序在更外层，就必须穿越补丁帧。触发源包括：
C++ throw、__try 内的访问违例、Probe 类防御失败、以及反作弊主动注册的
向量异常处理重扫。

**未对接时的后果**：穿越到补丁帧 → 查无展开信息 → 叶子假设 → 错误弹栈
→ 二次异常/死机。这就是必须做精确展开对接的原因。

**本轮对接方案（内核可见侧已实现）**：扩展已有的 RtlLookupFunctionEntry
元钩子——命中任一 PatchView 克隆区间时，返回目标模块 .pdata 的【原样
条目拷贝】并将 ImageBase 设为目标模块基址。由于补丁不改帧结构（字节替换
不改变 RSP 使用模型），原条目对克隆帧完全适用；UNWIND_INFO 与语言处理器
均指向真实模块内存，保真度 100%（含 C++ EH）。

**用户态分发侧的边界**：游戏自身的用户态 SEH/C++ 分发走 ntdll 的
RtlLookupFunctionEntry（独立实现），本轮未挂接——即游戏内部 C++ 异常
穿越补丁帧时仍走旧的不精确路径。完整方案需将元钩子扩展至 ntdll 版本
（懒安装于首个用户补丁创建时，全系统共享页一次覆盖），列为下一阶段。

### 已知边界

- 异常穿越补丁帧的展开精确化：待复用内核侧元钩子思路对接用户态动态表
  （游戏 C++ 异常频繁，铺开前必须解决——见第七节同条目）；
- 共享 DLL 页重映射全局生效（建议仅补丁 EXE 私有代码页）；
- 换页漂移：目标页被修剪出工作集后 GPA 失效（活跃代码通常常驻；长期
  需工作集锁定或换页拦截）；
- 计时侧信道同样适用于补丁页（每次读取一对 VMExit）。

## 七、跨版本兼容性评估

| 组件 | 版本依赖 | 结论 |
|---|---|---|

| 元钩子有效性前提 | "导出符号 = 实现体"。内核内部异常分发直调同一函数体字节时才可拦截 | 各版本历史成立；已加运行时自检兜底（见下） |
| `ExAllocatePool2` / `POOL_FLAG_*` / `POOL_FLAG_NON_PAGED_EXECUTE` | ≥ Win10 19041 | 驱动整体基线（既有约束） |
| PEB 偏移 0x550（BeingDebugged 清除） | 已验证 19041~26100；越界构建校验失败自动降级为"不清除"（不崩） | 见 BeingDebugged 修复说明 |
| SSDT 解析 / `PsGetProcessImageFileName` 等 | 导出或结构稳定 | 全版本 |

**元钩子自检**：每次安装克隆后经导出入口查询自身克隆区间，必须命中
自建条目方视为精确展开生效；失败则打日志 `[hook] unwind selftest FAIL`
并自动降级为旧的不精确展开（稳定性不受影响）。该自检覆盖外部调用路径；
内核内部异常分发若在特定构建上绕过导出入口直调内部实现，自检无法覆盖，
需实测验证（当前主流构建均为导出=实现体形态）。

**实测矩阵**：仅 26100（Win11 24H2, HVCI off）完整验证。19041~22H2 与
24H2 的差异点均在上述兼容层内，理论兼容；跨大版本部署前建议先跑一遍
第八节验收清单。
