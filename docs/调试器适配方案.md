# X64DBG 适配与全链路隐藏方案（NptBreakPoint）

> 目标：**X64DBG 以原生操作方式工作**（F2 下断点、F8 单步、附加进程、读写内存），
> 整条调试链路从**启动调试器开始**对反作弊不可见——不修改任何 Guest 字节、
> 不留调试痕迹。
>
> 参考：看雪《基于VT EPT的无痕断点无痕hook原理及其应用》§三（VT 调试插件路线）。
> **不做 WinDbg 内核 KD 适配**（KD 接管为产品级工作，超出当前范围）。

---

## 1. 全链路隐藏：从"启动 X64DBG"到"断点命中"

```
① 启动 X64DBG
     → 进程/窗口特征：反作弊常扫调试器进程 —— 内核侧可做模块隐藏（SELF_HIDE），
       进程特征属用户态对抗（文档注明，不在本驱动范围）
② X64DBG 附加目标（DebugActiveProcess）
     → 目标进程设置 DebugPort/DebugObject → 反作弊查询：
       被 NtQueryInformationProcess Hook 伪造（见 §2）✅
③ F2 软件断点（写 0xCC 到目标内存）
     → NtWriteVirtualMemory 被拦截：0xCC 不落内存，
       自动转为 NPT 无痕断点（影子页 CC）✅
④ 断点命中（CPU 取指 → 影子页 0xCC → #BP VMEXIT）
     → 注入 #BP 给 Guest 调试体系 → X64DBG 原生收到 EXCEPTION_BREAKPOINT ✅
     （内存始终无 CC：反作弊扫描/CRC 看不到断点）
⑤ F8 单步
     → RFLAGS.TF → #DB 拦截（未命中本框架时回落注入）→ X64DBG 收到 ✅
⑥ 读写内存
     → NtReadVirtualMemory 物理直读（真实内容）✅
     → NtWriteVirtualMemory 非 0xCC 写放行（调试器正常写值）✅
⑦ 硬件断点（F2→Hardware）
     → drprobe：DR 写被 SVM 拦截（假 DR 记录）→ 调试器读 DR 回显假值 ✅
```

## 2. 已实现的隐藏层（NpDebugHide 服务）

| 检测面（反作弊查询）| 处理 | 状态 |
|--------------------|------|------|
| `ProcessDebugPort`（NtQueryInformationProcess class 7）| 返回 0 | ✅ |
| `ProcessDebugObjectHandle`（class 0x1E）| 返回 STATUS_PORT_NOT_SET | ✅ |
| `ProcessDebugFlags`（class 0x1F）| 返回 1（可调试，未附加）| ✅ |
| 内存中 0xCC（软件断点）| 写拦截 → NPT 无痕断点（不落内存）| ✅ |
| 读内存监控（NtReadVirtualMemory 钩子）| 物理直读（NpMemAccess）| ✅ |
| DR0-3/DR7（硬件断点）| SVM DR 拦截（drprobe）：探测+伪造 | ✅ |
| TF/DR6（单步）| #DB 拦截回落注入 | ✅ |

**受保护进程集**：`NpHvCtl dbg protect <pid>` 注册调试目标，隐藏只对目标进程
生效，普通进程的 IO 零影响。Hook 用 NpHook 无痕框架（不落任何字节）。

**两种隐藏范围（模式）**：

| 模式 | 命令 | 语义 |
|------|------|------|
| 白名单（默认）| `dbg mode white` | 仅注册的 PID 隐藏 |
| 黑名单 | `dbg mode black` | **除注册的 PID 外，所有进程都隐藏**（注册 = 排除项）|

黑名单模式下：任何进程的 DebugPort/DebugObjectHandle/DebugFlags 查询都被伪造、
任何进程被写 0xCC 都会转为 NPT 无痕断点、任何读都走物理直读——只有 `dbg protect`
注册的 PID 保持"正常"（调试行为可见）。适合"全系统调试隐身 + 放行少数
需要正常调试行为的进程"。注意：黑名单模式下 0xCC 写拦截对所有进程生效，
误判（程序自写 0xCC 数据）会自动回落放行（断点安装失败时），且 NPT 断点
受每 CPU PT 页池（64）限制。

**断点透传模式**（`NPHV_BP_FLAG_DEBUGGER`）：命中后模拟"处理器执行了 INT3"——
RIP=NRip(INT3+1)、影子页放行原指令、注入 #BP → Guest KiDispatchException →
X64DBG 原生收到断点事件并暂停。**继续闭环**：命中置 `DebuggerPaused`（复位
线程跳过，保持放行）；调试器 continue 时重写 0xCC → 拦截 + 重新武装（NX=1）→
下次执行到断点再触发，杜绝"断点粘住"或 0xCC 真落内存。

## 3. X64DBG 原生操作方式（无需插件，**无需手动 protect**）

```bat
:: 一次配置（只开两个开关）：
NpHvCtl drprobe on                    :: 硬件断点接管
NpHvCtl dbg hide on                   :: 调试链路隐藏（Hook 5 个 Nt* 函数）

:: 之后完全原生操作 X64DBG，一切自动：
::   附加目标       → NtDebugActiveProcess 被拦截 → 目标自动保护 + 自动 drprobe
::   F2 软件断点    → 写 0xCC 被拦截 → NPT 无痕断点（内存无 CC）
::   断点命中       → 注入 #BP → X64DBG 原生暂停
::   F8 单步/F9 继续 → X64DBG 临时移除断点 → 单步 → 恢复断点（自动重新武装）
::   F2 硬件断点    → SetContextThread 写 DR → 自动转 NPT 断点/监视
::   查看堆栈/反汇编 → NtReadVirtualMemory → 物理直读（真实内容）
:: 反作弊视角：DebugPort=0、无调试对象、内存无断点字节、DR 为假值
```

**关闭会话**：`NpHvCtl drprobe off`、`NpHvCtl dbg hide off`。
（`dbg protect <pid>` 仍可用：手动指定调试目标，或黑名单模式下放行某进程。）

## 4. 无痕断点命中 → X64DBG 事件流（关键设计）

```
X64DBG F2 → NtWriteVirtualMemory(addr, 0xCC)
  → NpDebugHide 拦截：NpBreakPointInstallEx(addr, DEBUGGER) → 拦截写
  → 目标进程执行到 addr：
      取指 → NPT 影子页0(NX) → #NPF → 影子页1(0xCC) → #BP VMEXIT
  → NpBreakPointHandleBreakpoint：
      DEBUGGER 模式 → Rip=NRip、影子页0 NX=0、注入 #BP（EventInj vec3）
  → Guest KiDispatchException → 调试器回调 → X64DBG 暂停（断点命中 UI）
  → X64DBG F9 继续 → 线程从断点地址执行原指令（NPT 放行）
  → 复位线程（5ms）拉回 NX=1 → 断点重新武装
```

调试器看到的行为与普通 INT3 断点完全一致；内存、DR、调试 API 全部无痕。

## 5. 反作弊检测面覆盖情况

| 检测手段 | 覆盖 | 说明 |
|----------|------|------|
| ProcessDebugPort/DebugObjectHandle/DebugFlags | ✅ | API 层伪造 |
| PEB.BeingDebugged / ProcessHeap.Flags | ⚠️ 未做 | 需 NPT 双视图或事件驱动清除（后续） |
| 扫内存 0xCC | ✅ | 断点不落真实内存 |
| 查 DR0-3/DR7 | ✅ | DR 虚拟化（假 DR） |
| RDTSC 计时侧信道 | ⚠️ 未做 | VMEXIT 开销补偿（架构就绪） |
| 调试器进程/窗口特征 | ⚠️ 未做 | 用户态对抗（不在驱动范围） |
| NtSetContextThread 跨线程 DR 归属 | ⚠️ 未做 | 可叠加 NtSetContextThread Hook |

## 6. 验证步骤（AMD 实机 / 嵌套虚拟化 VM）

```bat
sc start NpHv
NpHvCtl drprobe on
NpHvCtl dbg hide on
:: 启动一个测试进程（如 notepad）
NpHvCtl dbg protect <notepad的PID>

:: 用 X64DBG 附加 notepad：
::   F2 在 MessageBoxA 设断点 → NpHvCtl bplist 应看到新断点（DEBUGGER 标志）
::   触发 MessageBoxA → X64DBG 应正常暂停（断点命中）
::   NpHvCtl bplist → hit 计数增长
::   F8 单步 / F9 继续 → 正常
::   任务管理器/反作弊工具 → DebugPort 查询返回 0

NpHvCtl dbg hide off
NpHvCtl drprobe off
```
